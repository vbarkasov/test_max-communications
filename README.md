# Чат с MAX через GREEN-API

Тестовое задание на позицию «Фронтенд-разработчик React»: пользовательский интерфейс
для отправки и получения текстовых сообщений в мессенджере **MAX** через
**GREEN-API MAX API** (<https://green-api.com/max>).

Внешний вид прототипа повторяет веб-версию MAX (<https://web.max.ru/>): сайдбар со
списком чатов, градиентный фон переписки, цветные пузыри сообщений, индикаторы
статусов доставки и прочтения.

## Возможности

- подключение к инстансу GREEN-API по `apiUrl` / `idInstance` / `apiTokenInstance`;
- проверка номера получателя и создание чата (`CheckAccount`);
- отправка текстовых сообщений (`SendMessage`) с оптимистичным обновлением интерфейса;
- приём входящих сообщений через технологию HTTP API
  (`ReceiveNotification` + `DeleteNotification`);
- статусы отправленных сообщений (`sent` / `delivered` / `read` / `failed`);
- адаптивная вёрстка и поддержка тёмной темы;
- сохранение учётных данных и списка чатов в `localStorage`.

Медиа, голосовые сообщения, реакции, группы, звонки и цитирование намеренно не
реализованы — по условию задачи нужен минимальный прототип.

## Настройка GREEN-API

1. Зарегистрируйтесь в [личном кабинете GREEN-API](https://console.green-api.com)
   и создайте инстанс с тарифом, поддерживающим MAX.
2. Авторизуйте инстанс (QR-код в разделе «Получить QR-код»). Без авторизации
   отправка и приём не работают.
3. Скопируйте из карточки инстанса три значения: `apiUrl`, `idInstance`,
   `apiTokenInstance`.
4. В приложении оставьте галочку «Настроить приём уведомлений через HTTP API» —
   приложение само вызовет `SetSettings` с пустым `webhookUrl` и включёнными
   `incomingWebhook`, `outgoingWebhook`, `outgoingMessageWebhook` и `stateWebhook`.
   Без пустого `webhookUrl` метод `ReceiveNotification` отвечает ошибкой
   `Message cannot be received because custom webhook url is set`.

> **Важно:** `SetSettings` вызывается только в момент подключения. Если инстанс уже
> подключён, а настройки менялись — отключитесь и подключитесь заново либо
> примените галочку вручную в личном кабинете. Иначе сервер продолжит работать со
> старыми настройками.

Два исходящих флага в MAX означают разное, и их легко перепутать:

| Флаг | Что приносит |
| --- | --- |
| `outgoingMessageWebhook` | сообщения, отправленные **с телефона**, из web и desktop версий |
| `outgoingWebhook` | **статусы** отправленных сообщений (`sent`, `delivered`, `read`) |

Без первого приложение не увидит сообщений, написанных вами в самом мессенджере.

## Как это работает

### Отправка

`POST {apiUrl}/waInstance{idInstance}/sendMessage/{apiTokenInstance}`

```json
{ "chatId": "10000000", "message": "Привет!" }
```

### Приём

HTTP API — это длинный опрос, а не push:

1. `GET {apiUrl}/waInstance{idInstance}/receiveNotification/{apiTokenInstance}?receiveTimeout=20`
   возвращает `{ receiptId, body }`, либо пустой ответ по таймауту.
2. Уведомление обрабатывается и **всегда** подтверждается вызовом
   `DELETE {apiUrl}/waInstance{idInstance}/deleteNotification/{apiTokenInstance}/{receiptId}`.
   Если этого не сделать, уведомление останется в FIFO-очереди на 24 часа и
   заблокирует все следующие.

Разбираются события `incomingMessageReceived` (тип `textMessage`),
`outgoingMessageReceived`, `outgoingMessageStatus` и `stateInstanceChanged`.
Цикл живёт в `useNotifications` и останавливается через `AbortController` при
размонтировании или смене учётных данных.

### Важная особенность MAX: `chatId` — это не номер телефона

В ответах GREEN-API для MAX `chatId` выглядит как `"10000000"`, а не как
`79991234567@c.us`. Отправка по номеру телефона работает только для совместимости
с прежними версиями, и тогда сервер не привязывает входящие уведомления к чату.
Поэтому приложение сначала вызывает `CheckAccount`, получает настоящий `chatId` и
только потом отправляет в него сообщения.

## Ограничения

- **Номера только РФ и РБ.** `CheckAccount` и отправка по номеру принимают
  `7…` (11 цифр) и `375…` (12 цифр). Номер с восьмёркой набирается как `7`.
  Номера других стран не поддерживаются.
- **Токен хранится в браузере.** В прототипе `apiTokenInstance` лежит в
  `localStorage` и виден в DevTools — так как задача проверяет именно фронтенд и
  всё общение идёт напрямую из браузера. Для продакшена нужен небольшой
  BFF-прокси, который хранит токен на сервере.
- **CORS.** Запросы идут напрямую на `api.green-api.com`; хост отвечает
  `Access-Control-Allow-Origin: *`, поэтому проксировать в dev-режиме не нужно.
  Значение `apiUrl` берите из личного кабинета: префикс `/v3` на конце адреса
  убирается автоматически.
- **История сообщений не подгружается.** `GetChatHistory` не вызывается: чат
  показывает сообщения, отправленные и полученные за время текущей сессии в этом
  браузере.
- **Один активный чат.** Список чатов — это то, что создано в текущем браузере;
  переключение работает между ними.

## Структура

```
src/
  api/
    greenApi.ts        HTTP-клиент GREEN-API: 6 методов, нормализация, разбор ошибок
    types.ts           типы ответов и уведомлений
  hooks/
    useNotifications.ts цикл ReceiveNotification → DeleteNotification
    useChats.ts        состояние чатов и сообщений (useReducer + localStorage)
  components/          LoginForm, Sidebar, NewChatDialog, ChatHeader,
                       MessageList, MessageBubble, MessageInput, ConnectionStatus
  chat.ts              модель сообщений и форматирование
  storage.ts           работа с localStorage
  index.css            дизайн-токены MAX и стили
  App.tsx              связывание состояния и компонентов
```

Состояние чатов и сообщений хранится в `useReducer`, обмен с API — в отдельном
слое `api/greenApi.ts`, поэтому компоненты не знают про URL GREEN-API.
